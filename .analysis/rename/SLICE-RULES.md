# 切片模式附加规则

你要处理的不是一个普通模块，而是**一个大 chunk 的字节区间切片**。

背景：有些 chunk 是**聚合 chunk** —— 打包器把许多逻辑模块合进了同一个文件
（例如 8MB 的 `核心应用-Agent循环.wmzgeczq.js`，或 1.2MB 的 `认证-OAuth登录.419zdfz3.js`）。
它们导出的、仍混淆的名字动辄上千个，一次性读完没有意义，
所以按**声明位置**切成若干片段，每片一份 dossier。

## 与 `NAMING-RULES.md` 的两处差异（其余规则全部照旧）

1. **`module` 字段必须写**该 chunk 的**完整仓库相对路径**（dossier 第一行就是它）。
   同一 chunk 的所有切片都写同一个路径，合并时会按模块汇总。

2. **绝对不要写 `newFileName`**。这个文件本身不是「一个模块」，它是很多模块的容器，
   给它改名没有意义。只改导出名。

## 证据上的两点提醒

1. **调用点可能对不上**：dossier 里的调用点是按名字找的；同一个短名在引用方里
   也可能是它自己的局部变量。**以你在源码里读到的实现为准**，调用点只作旁证。
   若某个名字的调用点看起来不相关，直接去仓库里 grep 它的真实引用方。

2. **片段边界**：切片按行边界切，但若某个名字的实现很长，可能延伸到你看到的
   片段之外。dossier 顶部会提示；遇到时自己去读原文件对应位置。

## 这类文件的特殊之处

- 它内部的模块级绑定有 16,000+ 个，但**只有导出名值得改**（切片列出的就是）。
  同一片段里还有大量没导出的混淆名（形参、临时变量），**不要碰**。
- 新名不要与该 chunk 里**已有的**标识符重名。这种文件很大，重名会直接让模块解析失败。
  挑选名字前，在该文件里 grep 确认为空（返回 0 最安全；若已有同名标识符，换个名字）：
  `grep -c '\b你的新名\b' "<dossier 第一行列出的那个路径>"`

## 自检

```
cd .analysis/rename && node lint-plans.mjs <你的计划文件> <同编号的切片 json>
```

必须 `errors=0`。

## 回报（简短）

只回：本片几个名字 / 改名几条 / 跳过几个及一句话原因 / lint 输出。**不要逐条列证据。**
